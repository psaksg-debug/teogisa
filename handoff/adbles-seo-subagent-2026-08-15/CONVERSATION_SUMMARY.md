# 대화 요구사항 요약

## 조직

- 사용자는 홍보부를 실제 운영 조직처럼 구성하고 검색엔진별 SEO를 지속 관리하도록 요청했다.
- 이름은 짧고 임팩트 있는 닉네임을 사용한다.
- 홍보부 담당은 픽, 랭크, 네오, 빙고, 소스, 크롤, 펄스로 정리되었다.
- 편집자는 글 작성 시 노출되는 이름을 가져야 하며 사용자는 여섯 명을 각각 정하라고 요청했다.
- 부장/책임편집자 이름은 현재 코드에서 `데스크`다.
- 마케팅 활동도 SEO와 함께 수행하되 외부 게시·광고 집행은 승인 대상이다.

## 검색 노출

- 사이트 SEO 관련 개발과 운영을 계속하고 문제가 있으면 즉시 보고·조치한다.
- SEO 업무는 주기를 정해 자동 실행한다.
- Google뿐 아니라 Naver, Bing·Copilot, AI 검색·인용을 함께 관리한다.
- 색인부터 시작하며 robots.txt, sitemap.xml, RSS, canonical, noindex, 메타데이터, 구조화 데이터, 작성자, 내부 링크를 관리한다.
- 검색 노출을 높이기 위해 공식 출처·FAQ형 직접 답변·콘텐츠 최신성·검색 의도를 계속 개선한다.

## ads.txt·RSS·사이트맵

- AdSense 화면에서 `ads.txt 찾을 수 없음`이 반복되었다.
- Google Search Console에서 RSS를 사이트맵으로 제출했지만 `가져올 수 없음`이 발생했다.
- RSS 라우트와 robots.txt를 배포·검증하는 작업이 이어졌다.
- 사이트맵과 RSS의 글 URL이 실제 200 응답인지 반드시 대조해야 한다.

## Google 색인 장애

- 포스팅 URL 색인 요청에서 `색인 생성 요청이 거부됨`이 발생했다.
- 실시간 테스트는 `Robots.txt를 찾을 수 없음`으로 페이지 가져오기에 실패했다.
- 도메인은 과거 다른 사이트에 연결되어 이미 색인된 이력이 있었다.
- 한글 슬러그 글이 사이트맵에 있었지만 404였고, URL 디코딩·유니코드 정규화·이전 슬러그 호환으로 수정했다.
- 2026-08-15 확인에서는 과거 한글 URL과 현재 영문 URL이 모두 HTTP 200이었다.

## Cloudflare와 승인

- 사용자는 Cloudflare Production 배포 승인 방법을 물었고 이후 특정 RSS·robots 관련 배포를 승인했다.
- 승인은 당시 작업 범위에 한정한다. 서브에이전트가 새 배포, DNS, D1, Cloudflare 설정 변경을 하려면 새 승인을 받아야 한다.

## 현재 지속 요청

- `검색엔진에 노출되도록 활동을 계속해`가 최신 운영 방향이다.
- 현재 `seo` 자동화가 매일 오전 9시와 오후 6시에 활성화되어 있다.
- 검색엔진의 노출이나 순위를 보장하지 말고 기술 장애·콘텐츠 기회·성과 데이터를 구분해 보고한다.
